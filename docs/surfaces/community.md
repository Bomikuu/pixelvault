# Community surface brief

**Mode:** Operate. **Status:** implemented test-mode surface inside the user-pinned PixelVault identity; Mapbox token still required.

**Job:** a Philippine member compares understandable lending offers, inspects a limited public profile, and privately applies without broadcasting financial need.

**First viewport:** compact PixelVault masthead, the map beside a right control/posting container on desktop, and the first real result rows. One search field, one map/list action and one radius select replace the former separate toolbars. Lead each result with lender identity, offered amount, total borrowing-cost example, frequency and approximate area. No preapproved-credit hero, fake activity or public borrower bidding wall.

**Sequence:** Explore → offer → term/schedule preview → private application → status. Profile and badge details are secondary evidence. A lender's Post an offer action has its own eligibility-aware route. Saved offers preserve the current immutable terms version; changes require a fresh comparison.

**Routes:** `/explore`, `/offers/:id`, `/offers/new`, `/members/:handle`, `/members/:handle/badges/:awardId`, `/applications/new?offer=:id`. The exact application is private even when the offer is public.

**Layout:** desktop opens a Mapbox workspace beside one right-side container for controls, live status, offer/recent-post tabs and scrolling results. On mobile the same controls precede the map and postings; list mode keeps complete comparable rows and the same control owner. Area, minimum amount and sorting use one canonical filter popover with an active-filter count. Zoom, fit/retry and optional device-location actions stay in the control container; Mapbox attribution stays on the map. Grouped avatar markers use approximate public area centroids without jitter or invented home locations. The list retains complete cost examples and pagination even when filtered loaded pages contain no matches.

**States:** no offers nearby, no matching loaded posts with more pages available, missing map configuration, geocoder/offline/WebGL/authorization failure, offer changed/closed, insufficient available amount, identity review required, applicant restricted, application already submitted, unavailable lender, long display name and stale saved offer. Preserve filters in URLs; precise coordinates never enter shareable URLs or public analytics.

**Success:** a member understands the counterparty, full cost and dates before applying. A specific verification check never suggests guaranteed repayment or government endorsement.

**Recent activity:** public posts have real server timestamps. SSE revision events and reconnects offer a staged refresh; they do not fabricate new-post counts or reorder a reader’s current view. An explicit 60-second polling fallback is labeled when streaming cannot recover.

**Community expression:** optional learning/contribution XP, an opt-in leaderboard, avatar frames and eligible badge flair support participation without borrowing incentives. A separate member sharing choice can publish aggregate lifetime lending, funded-loan count and distinct people helped; this never changes XP rank. Borrowing totals, individual debts and private recovery recognition stay private. The [leaderboard surface](leaderboard.md) records neutral podium cards, circular badge overflow, Tailwind styling and the shared light/dark toggle.

**Profile and offer expansion:** the [profile/social direction](profile-social-expansion.md) records the illustrated cover, larger photo/character, active profile tabs, private setup versus public XP progress, factual recommendation counts, earned-badge popup, interactive calculator and private consent invitation flow. Private contacts and co-borrowers are reachable from own-profile navigation. Likes/reactions never alter financial terms or XP; alternate calculator terms are comparison-only.

## Compact Explore controls and proximity

**Direction:** Operate; preserve Manrope, semantic blue/navy surfaces, factual loan examples and the incumbent avatar marker system. Consolidation changes control placement and behavior without replacing the visual world. The map/list action names its destination; it is one button. The shared illustrated discovery dialog gains an optional named icon-only trigger. All new feature styling uses Tailwind; obsolete discovery toolbar/layout CSS was removed. Existing offer likes, complete terms, recent posts and staged live updates remain.

**Search:** one field filters the loaded lender names, offer titles and area names locally. Its Find a place action sends a city/neighborhood query to Mapbox only on request. Results have context-qualified accessible names; pending/error/empty states and keyboard/touch actions remain available. Selecting a provider result clears the text query, centers the map and applies the current radius or a 10 km default. Missing configuration still permits local searches and complete lists.

**Proximity:** Any distance, 5, 10 and 50 km. The initial center is explicitly named Quezon City; selected provider areas or an explicitly requested device location replace it. Device coordinates and provider centers stay in component memory, never query URLs or application records. Reloading returns to the named default center. Only the safe radius and existing text/filter/view choices appear in URLs. Reset search center is in secondary filters; empty-state Clear filters resets the center and filters. Location is requested only by a user action, with unavailable/denied/timeout/out-of-country messages and stale request cancellation. No permission was requested during review.

**Map and list relationship:** the same validated public approximate area centers drive grouping and haversine radius filtering; unmapped/precise/invalid centers are excluded only while a radius is active. Mapbox draws a geodesic polygon, dashed boundary and origin dot, and fits its bounds on radius/place changes or Fit search area. The offer count, map markers and list share the filtered loaded set. More-page caveats and Load more remain reachable, including an empty filtered page. Recent posts explicitly cover all areas before these filters.

**Hover/focus:** entering an offer item or focusing its descendants highlights the corresponding grouped avatar pin, uses that member as its representative, raises it above other markers and adds a restrained scale/border/ring treatment. This transient state never moves the camera. Leaving the item restores the selected/default marker. Clicking a map pin or the explicit offer pin action retains selection and camera behavior. Reduced motion removes transitions. Pin/zoom actions are disabled when the map cannot render; Retry map remains in the right container.

**Verification:** visual/browser only under the continuing user override. No builds, automated tests, typecheck, UI check, contrast script or detector ran. The pass covered 1440px desktop, 390px mobile and 320px narrow layout, both themes, one-field lender/area search, real Mapbox Pasig/Marikina results and selection, the 5/10/50 km options, list/map switching, secondary filters, empty-state recovery and the illustrated information dialog. A 5 km Quezon City search narrowed four synthetic offers to one; 5 km around selected Pasig returned its matching offer; 50 km around Marikina showed all four. Narrow map/list observations showed no document overflow, and the captured browser console had no warnings/errors. Evidence: ignored `.runtime/qa/explore-controls/`.

**Limits:** this review browser reports WebGL unsupported. The real map radius layers, marker hover/focus rendering, camera animation and zoom actions remain source-reviewed rather than visually verified. GPS permission/results and multi-page search boundaries were not exercised. The existing Mapbox tests were maintained for the layer API and relocated recovery command but were not executed. No synthetic map or fabricated activity replaced unavailable tiles.
