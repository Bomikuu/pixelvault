## Native compatibility gate

The separate React/TypeScript phone interface shares Django APIs, domain contracts, art and canonical controls with web. Browser/PWA runs at `/m/`; full analytics/admin/reference remain web surfaces. Capacitor configuration is source preparation, not a verified Android application.

Native authenticated transport currently fails closed. Before enabling it, prove session-cookie ownership, CSRF bootstrap/rotation, restart/expiry/sign-out/revocation, rejected invalid-CSRF writes, multipart uploads and actor-authorized binary downloads on a physical Android device. Do not weaken cookie flags, CORS or CSRF to make a WebView request succeed. No refresh token, bearer-login endpoint, base64 file bridge or insecure native API origin is implied.

Approved return links only navigate to allowlisted PixelVault records and refetch server state; they cannot accept a contract or assert collection/settlement. App Links require deployment verification. Native calls stay hidden pending device permission/network validation. Background calls, store publication and iOS are separate gates.

The PWA caches only a public static shell and selected bundled assets, never financial data or queued mutations. Its update prompt requires an explicit reload; native mode does not register this worker. Keep offline records unavailable until a new online session refresh.
