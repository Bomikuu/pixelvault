# Interactive marketplace development

Open [the marketplace](http://127.0.0.1:5178/marketplace). The responsive web route is separate from the existing Explore map and the phone app. Choose a city, sign in with an existing account and explicitly join. The test-account chooser on sign-in can fill the existing synthetic borrower/lender credentials; do not create identities or financial records to populate screenshots.

The page uses the existing API at 8008, PostgreSQL and Redis from `compose.yaml`. For local development, start the existing infrastructure with `docker compose up -d postgres redis`, apply the new `plaza.0001_initial` migration and run the existing web/API development commands. This implementation applied that migration using `--skip-checks` under the current visual-only policy; migration execution is not test evidence. No extra game server or engine is required.

`PLAZA_REDIS_URL` optionally selects a separate Redis endpoint; an empty/missing value uses the existing `REDIS_URL`. Presence keys use `pixelvault:plaza:v1:` and do not touch Celery keys. This version uses atomic Lua commands on a single non-clustered Redis service. Never use FLUSHDB/FLUSHALL to reset a room. Joining, replacing, leaving and TTL expiry are the normal lifecycle.

The API is responsible for one controlled character per account, 40 members per room, 15-second foreground heartbeats, 60-second leases and fixed-speed trajectories. Rooms exist for Quezon City, Manila, Makati and Pasig. Sprite positions are virtual coordinates; they are not physical location, proximity verification or street navigation. A replaced tab must explicitly join again to regain control.

The optional Google Maps background uses `VITE_GOOGLE_MAPS_API_KEY` from the root environment. Configure a browser key for Maps JavaScript API and the intended allowed websites/APIs, then restart Vite. No Maps key is currently installed locally. Without one, or on provider failure, the world uses the labeled original **Plaza view · Map unavailable**. Membership, sprites, bubbles and offers continue working. Do not paste a Mapbox token into this setting or ship the generated concept image as map tiles. See [Google's setup](https://developers.google.com/maps/documentation/javascript/get-api-key) and [custom-overlay lifecycle](https://developers.google.com/maps/documentation/javascript/customoverlays). Cloud setup/billing is an operator action, outside this implementation.

Google scripts load only on this route. Browser-native map attribution and zoom controls remain visible; the overlay adds a Find my character control. Map pan/zoom changes projection only. Actual provider delivery/recovery remains unverified until a key is configured.

Speech bubbles are public to room participants, limited to 120 Unicode code points, six posts/minute and one visible 60-second bubble per person. Newlines normalize to spaces; HTML-shaped text renders as text. Optional attachments must be the posting member's currently available offer in the same city. The composer receives a separate bounded own-offer projection so other lenders' recent posts do not crowd the member's choices out of the city feed. Bubbles are not contractual quotations; the current offer dialog and server calculator determine displayed costs/rate basis.

Report controls retain evidence for authorized moderator/admin staff at `/admin/plaza`. Reporting does not automatically sanction the author. Staff decisions require a current version/reason and are audited; self-moderation is refused. The daily Celery beat task `plaza.tasks.purge_expired_bubbles` removes expired content older than seven days unless an unresolved report requires retention. Run the existing worker/beat workflow for scheduled cleanup; merely starting Django does not run beat. Production retention/staffing still requires an explicit policy.

Proxy `/api/*` to Django, disable SSE buffering and allow the 45-second stream to complete. `plaza.changed` announces a revision; clients fetch an authorized fresh snapshot. There is no event replay promise, offline queue, per-frame request stream, private-chat replacement or financial command in this feature. Foreground REST polling provides a recovery path. Capacity and connection/resource behavior still need authorized load testing before public rollout.

The original pixel sprites are authored in `spriteData.ts`/`Sprite.tsx`, with four facing directions and a short walk cycle. Profile pictures remain in ordinary person/offer views. No new raster production asset, game artwork dependency, map screenshot, NPC peer or fabricated online count was added.

Automated release checks are described in [the evidence checklist](release-checklist.md). Test source exists but was not executed. Redis integration tests require an explicitly configured `PLAZA_TEST_REDIS_URL`; they create an isolated random prefix and delete only their own keys.
